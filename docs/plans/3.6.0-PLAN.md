# Activity Share 3.6.0 - Free + Pro rebuild plan

Canonical plan for **Wbcom Designs - BuddyPress Activity Social Share 3.6.0** (free, wp.org `bp-activity-social-share`)
and **BuddyPress Activity Share Pro 3.6.0** (paid). Both ship together. This file is the only copy; Pro links here.

Audit date: 2026-09-24. Every finding below was reproduced live on the wbcom-pro sandbox (BuddyPress 14.4, BuddyX + Reign) unless marked *code*.

## 1. Principles

1. **Pro extends Free. Zero duplicated code.** Every capability lives in exactly one plugin. Pro calls Free's API and hooks; it never ships its own copy of a share button, network list, setting, asset or helper.
2. **Judge by what owners and members expect**, not by what exists. Pre-existing is not an excuse.
3. **One data contract**, owned by Free, versioned, migrated once.
4. **Big-site ready on day one** (2000+ activities, 500+ members), mobile 390px, RTL, dark mode, keyboard + screen reader.

## 3. Architecture after 3.6.0

```
Free (bp-activity-social-share)            Pro (buddypress-activity-share-pro)
------------------------------------      ------------------------------------
Network registry  bpas_networks()   <----  adds nothing; reads registry
Settings store    bpas_get_setting() <---  own keys only for Pro features
Share menu render bpas_render_share_menu() fires bpas_share_menu_items -> Pro adds "Reshare" row
Assets (CSS/JS, RTL, dark tokens)   <----  Pro enqueues only reshare/analytics assets
OG meta, guest sharing, copy link,
native share, a11y
Admin shell + tabs (bpas_admin_tabs) <---  Pro registers Reshare / Post types / Analytics tabs
```

- Pro header: `Requires Plugins: bp-activity-social-share` (same pattern as WB Ad Manager Pro).
- Pro renames every class to `BPAS_Pro_*`, every constant to `BPAS_PRO_*`, every global function to `bpas_pro_*`. No shared symbol can collide again.
- Text domain = slug: Free `bp-activity-social-share` (required for translate.wordpress.org language packs, which never loaded under `buddypress-share`), Pro `buddypress-activity-share-pro`. Fresh POT for both.
- **Old Pro on new Free:** Free 3.6.0 detects Pro active with version `< 3.6.0`, does not boot its own frontend (so the 2.x copy keeps working), and shows one admin notice: "Update Activity Share Pro to 3.6.0". No fatal, no double buttons.

## 4. Data contract (Free owns it)

| Key | Shape | Replaces |
|---|---|---|
| `bpas_settings` (option) | `{ networks: ['facebook','x',...] ordered enabled slugs, open_popup: bool, guest_share: bool, icon_style: 'brand'\|'mono'\|'outline', colors: {...} }` | `bp_share_services` (3 shapes), `bp_share_services_extra`, `bp_share_services_logout_enable`, `bp_share_services_enable`, `bpas_icon_color_settings`, `bp_share_services_serialized`, `bp_share_flag` |
| `bpas_db_version` (option) | `'3.6.0'` | `bp_share_db_version` (was written by Free, read by Pro) |
| `bpas_pro_settings` (option, Pro) | reshare + restrictions + tracking | `bp_reshare_settings`, Pro keys inside `bp_share_services_extra` |
| `bpas_pro_db_version` (option, Pro) | `'3.6.0'` | `bp_share_plugin_version` |

- **One migration**, run on `plugins_loaded` when `bpas_db_version` < code version (never tied to the activation hook). Reads every legacy shape (Name=>Label, `chb_*` arrays, lowercase keys, `X`/`Twitter`, `Pocket`) and writes the new option.
- Legacy keys are **left untouched** until 3.7.0 so a rollback to 3.5.x / 2.3.0 still works; uninstall removes both.
- Single site uses `get_option`; network-activated multisite reads the network value as default. One accessor, no mixed `get_site_option` / `get_option` reads.

## 10. Execution plan - fresh build

Both plugins are rebuilt as new code on their `3.6.0` branches. Nothing from 3.5.x / 2.3.x is carried over except: the **main file names** (`bp-activity-social-share/buddypress-share.php`, `buddypress-activity-share-pro/buddypress-share.php` - renaming them would deactivate the plugin on every site at update), the legacy option keys the migration reads, and Pro's existing share-count meta. Layout mirrors Jetonomy (reference implementation): namespaced classes in `includes/` with WordPress file names, Grunt + rtlcss for CSS, `bin/` for CI and release.

### 10.5 CSS and JS architecture

**Markup (one template for every surface):**
`<details class="bpas-share">` with a `<summary>` button ("Share", aria-label includes the object) and a `role="group"` panel. `<details>` gives open / close with no JavaScript, so the no-JS fallback is native. Each network is an `<a>` with `aria-label="Share on {Network}"`, 44px target, `rel="noopener nofollow"`, `target="_blank"`. Copy link and native share are `<button>`s; native share starts `hidden`.

**CSS:**
- `bpas-tokens.css`: `--bpas-*` tokens chained BuddyX `--bx-color-*` -> legacy BuddyX -> Reign `--reign-*` -> Astra / Kadence / Blocksy / GP -> `--wp--preset--*` -> hex; root dark override for themes without their own; brand colours as `--bpas-brand-{slug}` set from settings via `wp_add_inline_style`.
- `bpas-share.css`: component only, logical properties (RTL via rtlcss too), `:focus-visible`, hover guarded by `@media (hover: hover)`, reduced motion, exactly two media blocks (<= 1024px, <= 640px). At <= 640px the panel becomes a bottom sheet.
- Budget: share CSS <= 8 KB gz, admin <= 20 KB gz. No Font Awesome, no dashicons, no Bootstrap, no Select2 anywhere in either plugin.

**JS (`bpas-share.js`, ~3 KB):**
- Why not the Interactivity API: BuddyPress Nouveau appends activity via AJAX, and IAPI does not hydrate HTML injected outside its router, so directives on activity items would be dead after "Load more". One document-level delegated listener works for server-rendered and AJAX-appended items, with no re-init (standard section 3 rule 4: document-delegated is compliant).
- Handles: close other open menus / outside click / Escape (return focus to summary), popup window when enabled, copy link (`navigator.clipboard` + polite live region), native share (`navigator.share`, un-hide when supported), optional tracking ping (Pro listens to a `bpas:share` CustomEvent - Free fires it, Pro sends it).
- No jQuery, no inline scripts, data through `wp_add_inline_script( ..., 'before' )`.

**Pro composer (`bpas-pro-composer.js`):** native `<dialog>` (focus trap + Escape for free), destination `<select>` (my profile / a group / a friend) with a search box that queries REST when the member has more than 50 groups, textarea with BuddyPress `bp-suggestions` for @mentions, loading / error / success states, posts via `apiFetch` to `bpas/v1/reshare`.

**Admin (`bpas-admin.js`):** vanilla, REST via `wp.apiFetch` (`bpas/v1/settings`), toast + promise confirm modal (no `alert` / `confirm`), networks list: checkboxes + move up / down buttons, drag as enhancement.

**Build:** Grunt (as Jetonomy): cssmin + rtlcss + uglify, `npm run build`; `bin/build-release.sh` builds the zip with `.distignore` (no docs/, audit/, bin/, tests/, *.md).

### 12.5 Developer extension: adding a share service

Owners never see developer options; developers extend through code only. Adding a network takes one call, and it then behaves exactly like a built-in one: listed on the Networks tab (off until the owner ticks it), orderable, rendered in every share menu (activity, profiles, groups, posts, block, shortcode), counted by Pro analytics.

```php
add_action( 'bpas_register_networks', function () {
    bpas_register_network( 'mastodon', array(
        'label'     => __( 'Mastodon', 'my-plugin' ),
        'share_url' => 'https://mastodonshare.com/?url={url}&text={title}', // placeholders: {url} {title} {text} {image}
        'icon'      => '<svg ...>...</svg>',  // inline SVG, sanitised with an SVG allowlist; or 'icon_url'
        'color'     => '#6364FF',             // brand colour used when "brand colours" is on
        'mobile'    => true,                  // show on phones (false = desktop only)
    ) );
} );
```

Rules enforced by Free: `https://` share URLs only, placeholders URL-encoded by Free (never by the caller), SVG sanitised (no scripts / event attributes), slug unique (`bpas_register_network` returns `WP_Error` on duplicates), built-ins can be removed with `bpas_unregister_network( 'pinterest' )` or relabelled through `bpas_networks`.

Other developer hooks stay code-only (10.4): `bpas_share_context` (change url / title / image), `bpas_share_menu_items` (add a custom row, e.g. "Save to bookmarks"), `bpas_can_share_externally`, `bpas_share_url` (append UTM / referral), `bpas_open_graph_enabled`, `bpas_pro_user_can_repost`, `bpas_pro_retention_days`. Documented with copy-paste examples in `docs/website/developer-guide/` (adding a network, adding a menu row, custom OG image). Adding a network is covered by an automated test so the contract cannot break silently.
